git merge vs git reverse


1️⃣ Git Merge

Command:
git merge feature-branch
What it does:
Combines the histories of two branches.
Creates a merge commit.

Example
Before merge
main
A---B---C
     \
      D---E  feature

After merge
main
A---B---C------F
     \        /
      D---E---
F = merge commit
✔ Preserves history
✔ Safe for teams

2️⃣ Git Rebase
Command:
git rebase main
What it does:
Moves your commits on top of another branch
Rewrites commit history.
Example
Before rebase
main
A---B---C
     \
      D---E  feature
After rebase
main
A---B---C---D'---E'
D' and E' are new commits.
✔ Clean linear history
✔ Easier to read logs

3️⃣ Golden rule of rebase
Never rebase shared branches.
If others already pulled the branch, rebasing can break their history.

4️⃣ When to use each
Use merge
Team branches
Shared repositories
Production branches
Example:
git checkout main
git merge feature
Use rebase
Cleaning up your local commits
Keeping history linear
Example workflow:
git checkout feature
git rebase main

5️⃣ Common professional workflow
Most teams use:
Rebase locally
Merge into main
Example:
git fetch
git rebase origin/main
git push

Then create a PR.

✅ Simple way to remember
Merge = preserve history
Rebase = rewrite history for cleanliness
