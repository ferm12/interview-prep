

Here’s a comprehensive guide on rendering strategies in web development, what they are, and when to use them. This is often a key topic for React, Next.js, or general front-end interviews.

1. Rendering Strategies Overview
Rendering strategies determine how and when your web pages or components are rendered, which affects:
Performance
SEO
User experience
Server load
Common rendering strategies include:
Client-Side Rendering (CSR)
Server-Side Rendering (SSR)
Static Site Generation (SSG)
Incremental Static Regeneration (ISR)
Hybrid Rendering
Streaming / Suspense Rendering (modern React)

2. Client-Side Rendering (CSR)
How it works:
Browser downloads HTML, CSS, JS
JS runs and builds the UI dynamically in the client
Often used in single-page applications (SPAs)

Pros:
Fast subsequent navigation (SPA)
Rich interactivity
Less server load

Cons:
Slow first paint / initial load
SEO can be challenging (though tools like prerendering help)
When to use CSR:
Dashboard apps
Internal tools
Apps with heavy interactivity and user authentication
Example:
// React SPA
function App() {
  const [data, setData] = useState([]);
  useEffect(() => {
    fetch("/api/data").then(res => res.json()).then(setData);
  }, []);
  return <div>{data.map(item => <p>{item.name}</p>)}</div>;
}

3. Server-Side Rendering (SSR)
How it works:
Server renders HTML dynamically for each request
Client receives fully formed HTML
Often used in Next.js with getServerSideProps

Pros:
Fast first contentful paint
Better SEO
Works well for dynamic content that changes per request

Cons:
Slower subsequent navigation unless combined with caching
Higher server load
When to use SSR:
E-commerce product pages
Blogs or news sites with dynamic personalized content
Pages where SEO is critical
Example (Next.js SSR):
export async function getServerSideProps(context) {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();
  return { props: { posts } };
}

4. Static Site Generation (SSG)
How it works:
HTML is generated at build time
Served as static files from CDN
Example: Next.js getStaticProps()
Pros:
Extremely fast, low server load
Excellent SEO
Can use CDN caching globally
Cons:
Content is not dynamic per request (unless combined with ISR)
When to use SSG:
Marketing pages
Documentation
Blog posts / landing pages
Example (Next.js SSG):
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();
  return { props: { posts } };
}

5. Incremental Static Regeneration (ISR)
How it works:
Hybrid of SSG and SSR
Pages are pre-generated at build time, but can be regenerated on-demand
Next.js: revalidate option

Pros:
Best of both worlds: fast + up-to-date content
Reduces server load vs SSR

Cons:
Slight delay for first visitor after regeneration
When to use ISR:
E-commerce catalogs with frequent updates
News portals
Large-scale static sites needing updates
Example (Next.js ISR):
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();
  return { props: { posts }, revalidate: 60 }; // regenerate every 60s
}

6. Hybrid Rendering
Combining SSR, SSG, CSR in a single app
Example: Next.js app with static landing pages (SSG) + dynamic dashboard (CSR)
When to use:
Large apps with both marketing pages and user dashboards

7. Streaming / Suspense Rendering (React 18+)
How it works:
React can stream HTML from server
Show loading UI while other components are still fetching
Great for slow APIs or large pages

Pros:
Faster perceived load
Better user experience

Cons:
Newer pattern, less common in traditional apps
Example:
<Suspense fallback={<Loading />}>
  <Profile userId={id} />
</Suspense>

8. Comparison Table
Strategy	When to Use		Pros				Cons
CSR		SPAs, dashboards	Fast navigation, interactive	Slow first load, SEO challenges
SSR		SEO-critical, dynamic	Fast first paint, SEO-friendly	High server load
SSG		Static sites, blogs	Fast, CDN-friendly		Not dynamic per request
ISR		Frequently updated 
		static sites		Fast + up-to-date		Slight delay on regeneration
Hybrid		Complex apps		Best of all worlds		More complex architecture
Streaming	Large pages, React 18+	Faster perceived load		Experimental for some cases

9. Interview Tips
Be ready to explain trade-offs: SEO vs performance vs server cost
Give real-world examples (e.g., “Marketing pages → SSG, Dashboards → CSR”)
Mention Next.js if React is involved
Discuss caching and CDNs when relevant

What is A/B testing?
A/B testing (also called split testing) is a controlled experiment where:
Users are randomly split into two or more variants
Each group sees a different version of a page or feature
Performance is measured using predefined metrics
The variant with better results is chosen
