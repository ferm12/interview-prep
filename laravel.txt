LARAVEL

🧱 What is MVC?

MVC stands for:

Model – Manages data and business logic (interacts with DB)
View – UI, what the user sees
Controller – Handles requests, updates the model and view
Laravel follows this architecture to cleanly separate concerns in your web application.

🚀 Getting Started with Laravel

✅ Prerequisites:
PHP 8.x+
Composer (PHP package manager)
MySQL or other DB
Web server (Apache/Nginx or Laravel's built-in server)
🔧 Step 1: Install Laravel

Open your terminal and run:

composer create-project laravel/laravel myApp
cd myApp
php artisan serve
Visit http://localhost:8000 to see your new Laravel app.

📁 Step 2: Laravel Folder Structure (MVC Focus)

app/Models – Your Model files (e.g., User.php)
resources/views – Your View files (e.g., welcome.blade.php)
app/Http/Controllers – Your Controllers (e.g., PostController.php)
routes/web.php – Your app's routes
🛠️ Step 3: Create a Model, View, Controller

Let’s build a simple Post resource.

1. Create Model, Migration, and Controller:
php artisan make:model Post -m
php artisan make:controller PostController
This creates:
app/Models/Post.php
database/migrations/xxxx_create_posts_table.php
app/Http/Controllers/PostController.php
2. Define Database Schema
Edit the migration file:

public function up()
{
    Schema::create('posts', function (Blueprint $table) {
        $table->id();
        $table->string('title');
        $table->text('content');
        $table->timestamps();
    });
}
Run migration:

php artisan migrate
3. Define Routes
Edit routes/web.php:

use App\Http\Controllers\PostController;

Route::get('/posts', [PostController::class, 'index']);
4. Controller Logic (PostController)
use App\Models\Post;

public function index() {
    $posts = Post::all();
    return view('posts.index', compact('posts'));
}
5. Create View
Create a Blade view: resources/views/posts/index.blade.php

<!DOCTYPE html>
<html>
<head>
    <title>Posts</title>
</head>
<body>
    <h1>All Posts</h1>
    <ul>
        @foreach($posts as $post)
            <li>{{ $post->title }}</li>
        @endforeach
    </ul>
</body>
</html>
🌐 Now visit http://localhost:8000/posts

You’ll see all your posts displayed using Laravel’s MVC structure!

📚 What Next?

Learn about:
Resource controllers (php artisan make:controller --resource)
Eloquent relationships
Validation
Authentication (Laravel Breeze, Jetstream)
API routes

ARTISAN

What is Artisan?

Artisan is a built-in tool in Laravel that provides a set of commands to help with:

Generating code (controllers, models, migrations, etc.)
Running database migrations
Starting a development server
Clearing cache/config
Creating custom commands
Managing scheduled tasks and queues
It lives in the root of your Laravel project as artisan.

✅ Common Artisan Commands

Command	Description
php artisan serve	Starts the Laravel dev server at http://localhost:8000
php artisan make:controller PostController	Creates a new controller
php artisan make:model Post	Creates a model
php artisan make:migration create_posts_table	Creates a migration file
php artisan migrate	Runs all database migrations
php artisan route:list	Lists all your app’s routes
php artisan tinker	Opens an interactive shell for testing your Laravel code
php artisan cache:clear	Clears the cache
php artisan config:clear	Clears the config cache
php artisan make:command CustomCommand	Creates a custom Artisan command
🧪 Example Usage

php artisan make:model Product -mcr
This single command creates:

Model: app/Models/Product.php
Migration: for products table
Controller: ProductController.php with resource methods
🛠️ Custom Artisan Commands

You can even create your own command:

php artisan make:command GreetUser
This creates a file in app/Console/Commands, where you can define logic and then run:

php artisan greet:user

ORM - ELOQUENT

In Laravel, the ORM (Object-Relational Mapper) is called Eloquent. It allows you to interact with your database using PHP objects instead of writing raw SQL.

🧱 What Is Eloquent ORM?

Eloquent provides a simple Active Record implementation. Each database table has a corresponding Model class that is used to:

Retrieve records
Insert new records
Update records
Delete records
Define relationships between tables
🚀 Getting Started with Eloquent

✅ Create a Model and Migration
php artisan make:model Post -m
This creates:

A model: app/Models/Post.php
A migration: database/migrations/xxxx_create_posts_table.php
📦 Basic CRUD with Eloquent

Assuming a posts table with title and content columns:

🔍 Read Records
use App\Models\Post;

$allPosts = Post::all();              // Get all records
$post = Post::find(1);                // Find by primary key
$drafts = Post::where('status', 'draft')->get();  // Conditional query
✍️ Create Record
Post::create([
    'title' => 'New Post',
    'content' => 'This is a new post'
]);
🔐 You must define $fillable in your model:
protected $fillable = ['title', 'content'];
🔁 Update Record
$post = Post::find(1);
$post->title = 'Updated Title';
$post->save();
🗑️ Delete Record
$post = Post::find(1);
$post->delete();
Or:

Post::destroy(1);
🔗 Eloquent Relationships

1. One to Many
User has many Posts

// In User.php
public function posts() {
    return $this->hasMany(Post::class);
}

// In Post.php
public function user() {
    return $this->belongsTo(User::class);
}
2. Many to Many
Post belongs to many Tags

public function tags() {
    return $this->belongsToMany(Tag::class);
}
3. One to One
public function profile() {
    return $this->hasOne(Profile::class);
}
📚 Eloquent Features

Mass Assignment: create() and update() with $fillable
Query Scopes: Custom filters like ->active()
Accessors & Mutators: Format data when getting/setting attributes
Soft Deletes: Use SoftDeletes trait to mark records as deleted
Eager Loading: Use with() to avoid N+1 queries
Post::with('user')->get();
🧪 Eloquent in Tinker (for testing)

php artisan tinker
>>> Post::where('status', 'published')->count();

BLADE

In Laravel, Blade is the templating engine used to create views (HTML pages) in a clean, readable, and dynamic way.

🪄 What is Blade?

Blade lets you write PHP code inside your HTML with elegant syntax. It compiles into plain PHP and is super fast.

Blade files have the extension:

.blade.php
Example:
resources/views/welcome.blade.php

🧠 Blade Syntax Basics

✅ Echoing Variables
<h1>Hello, {{ $name }}!</h1>
✅ Control Structures
If/Else

@if ($user->isAdmin())
    <p>Welcome Admin</p>
@else
    <p>Welcome User</p>
@endif
Loops

@foreach ($posts as $post)
    <li>{{ $post->title }}</li>
@endforeach
You can also use:

@for
@while
@isset
@empty
🧩 Blade Components

Reusable UI pieces.

Create a component:

php artisan make:component Alert
It creates:

Class: app/View/Components/Alert.php
View: resources/views/components/alert.blade.php
Usage:

<x-alert type="error" message="Something went wrong!" />
🔁 Template Inheritance

Use layouts to avoid repeating HTML structure.

layout.blade.php

<!DOCTYPE html>
<html>
<head>
    <title>@yield('title')</title>
</head>
<body>
    @yield('content')
</body>
</html>
home.blade.php

@extends('layout')

@section('title', 'Home Page')

@section('content')
    <h1>Welcome Home</h1>
@endsection
✨ Blade Directives

Directive	Purpose
@csrf	Adds CSRF token to forms
@method('PUT')	Spoof HTTP method
@include('viewname')	Includes another Blade view
@component	Embeds a component
@vite	Include compiled assets (CSS/JS)
@auth, @guest	Auth-based content display
📌 Example

@extends('layout')

@section('title', 'Posts')

@section('content')
    <h1>All Posts</h1>
    @foreach($posts as $post)
        <div>
            <h2>{{ $post->title }}</h2>
            <p>{{ $post->content }}</p>
        </div>
    @endforeach
@endsection

SQL OPTIMIZATION:
			
SQL query optimization is the process of improving the performance of your SQL queries so they run faster and use fewer resources (CPU, memory, I/O).

🎯 Why Optimize?

Faster page loads
Reduced server load
Better scalability
Improved user experience
🔧 Key SQL Optimization Techniques

1. Use SELECT Only What You Need
Avoid SELECT * — it retrieves unnecessary data.

✅ Good:

SELECT name, email FROM users;
🚫 Bad:

SELECT * FROM users;
2. Use Indexes Wisely
Indexes speed up WHERE, JOIN, ORDER BY, and GROUP BY operations.

✅ Example:

CREATE INDEX idx_users_email ON users(email);
But avoid over-indexing — each index slows down INSERT/UPDATE.

3. Filter Early with WHERE
Always use a WHERE clause to limit rows processed.

SELECT name FROM users WHERE active = 1;
4. Use Proper Joins and Reduce Data Early
Avoid unnecessary joins and reduce rows before joining.

SELECT u.name, o.total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.total > 100;
5. Use LIMIT for Pagination
Fetch only what you need:

SELECT * FROM posts LIMIT 10 OFFSET 20;
6. Avoid Functions on Indexed Columns in WHERE
This disables index usage.

🚫 Bad:

WHERE YEAR(created_at) = 2023
✅ Good:

WHERE created_at BETWEEN '2023-01-01' AND '2023-12-31'
7. Optimize COUNT, GROUP BY, and ORDER BY
Use COUNT(*) carefully; avoid on large tables without filters
Use indexed fields in ORDER BY
8. Use EXISTS Instead of IN (for large subqueries)
🚫 Bad:

SELECT name FROM users WHERE id IN (SELECT user_id FROM orders);
✅ Good:

SELECT name FROM users WHERE EXISTS (
  SELECT 1 FROM orders WHERE orders.user_id = users.id
);
9. Avoid N+1 Queries
Fetch related records with joins or subqueries instead of running one query per row.

10. Use EXPLAIN or EXPLAIN ANALYZE
See the query plan and understand how the database executes it.

EXPLAIN SELECT * FROM users WHERE email = 'x@example.com';
🛠️ Tools for Optimization

MySQL: EXPLAIN, SHOW PROFILE, Slow Query Log
PostgreSQL: EXPLAIN ANALYZE, pg_stat_statements
SQL Server: Query Analyzer
Online tools: EverSQL, ApexSQL
